You've trained a model in Python. How does it get into a Rust program? There are three routes, from simplest to most general.

## Route 1: export the numbers

A linear or logistic model is just a handful of numbers: the scaler's means and standard deviations, the weights and the biases. Export them in a simple format and re-implement `predict` in Rust (a few lines, as you've seen). This is also how most models reach a **microcontroller** (Phase 13), where there's no room for a general runtime.

Run this Python cell to train a small model and export it as text:

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(1)
X = rng.normal(size=(500, 2)) * [200, 1] + [0, 1.5]   # elo_diff, home_form
y = (X[:, 0] / 200 + 0.5 * X[:, 1] + rng.normal(size=500) > 0.75).astype(int)

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X, y)
scaler, clf = model.named_steps["standardscaler"], model.named_steps["logisticregression"]

lines = [
    "mean " + " ".join(f"{v:.6f}" for v in scaler.mean_),
    "scale " + " ".join(f"{v:.6f}" for v in scaler.scale_),
    "weights " + " ".join(f"{v:.6f}" for v in clf.coef_[0]),
    f"bias {clf.intercept_[0]:.6f}",
]
print("\n".join(lines))
print("check:", model.predict_proba([[120.0, 2.0]])[0, 1].round(6))
```

A Rust program reads that text and predicts. Always include a **check value** like the last line: one input and its expected output. After loading, the Rust side recomputes it and refuses to start if it doesn't match. That catches mixed-up feature orders, a missing scaler, or a stale model file, which are the most common deployment bugs.

Formats used in practice: JSON (with `serde_json`), `safetensors` (Hugging Face's safe, fast format for tensors, readable from Python and Rust), or plain Rust source code generated by a script, which is what you'll do for microcontrollers.

## Route 2: ONNX

**ONNX** (Open Neural Network Exchange) is a standard file format for models. PyTorch, scikit-learn (via `skl2onnx`), LightGBM and XGBoost can all export to it, and runtimes in every language can run it.

```python static
# scikit-learn → ONNX
from skl2onnx import to_onnx
onx = to_onnx(model, X[:1].astype(np.float32))
open("match_model.onnx", "wb").write(onx.SerializeToString())

# PyTorch → ONNX
torch.onnx.export(net, example_input, "net.onnx", input_names=["x"], output_names=["logits"])
```

In Rust, `ort` wraps Microsoft's ONNX Runtime (fastest, with GPU support), while `tract` is pure Rust (no C++ dependency, compiles for almost any target, including WebAssembly and small ARM boards):

```rust static
use tract_onnx::prelude::*;

fn main() -> TractResult<()> {
    let model = tract_onnx::onnx()
        .model_for_path("match_model.onnx")?
        .into_optimized()?
        .into_runnable()?;

    let input: Tensor = tract_ndarray::arr2(&[[120.0f32, 2.0]]).into();
    let outputs = model.run(tvec!(input.into()))?;
    println!("{:?}", outputs[0]);
    Ok(())
}
```

## Route 3: train or run in a Rust framework

Candle can load PyTorch `safetensors` weights directly into a model defined in Rust, and Burn can import ONNX models and generate Rust code from them. Use these for deep learning models where re-implementing the forward pass by hand isn't practical.

## Serving predictions

The Rust equivalent of the FastAPI service from Phase 8 uses **axum** (built on Tokio) and **serde** for JSON:

```rust static
use axum::{extract::State, routing::post, Json, Router};
use serde::{Deserialize, Serialize};
use std::sync::Arc;

#[derive(Deserialize)]
struct MatchFeatures {
    elo_diff: f64,
    home_form: f64,
}

#[derive(Serialize)]
struct Prediction {
    p_home_win: f64,
    model_version: &'static str,
}

async fn predict(State(model): State<Arc<Model>>, Json(f): Json<MatchFeatures>) -> Json<Prediction> {
    Json(Prediction { p_home_win: model.predict(&[f.elo_diff, f.home_form]), model_version: "2025-01" })
}

#[tokio::main]
async fn main() {
    let model = Arc::new(Model::load("model.txt").expect("model failed its check value"));
    let app = Router::new().route("/predict", post(predict)).with_state(model);
    let listener = tokio::net::TcpListener::bind("0.0.0.0:8000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

Compared with the FastAPI version: serde validates the JSON like Pydantic; the binary is a few megabytes with no Python runtime, so the Docker image can be tiny (`FROM scratch` or distroless); it starts in milliseconds; and it handles many thousands of requests per second on one core. The trade-off is slower development: keep FastAPI for most internal tools, and reach for Rust when latency, cost or footprint matter.

@@solution
#[derive(Debug)]
struct Model {
    mean: Vec<f64>,
    scale: Vec<f64>,
    weights: Vec<f64>,
    bias: f64,
}

fn numbers(values: &[&str]) -> Result<Vec<f64>, String> {
    values.iter().map(|v| v.parse::<f64>().map_err(|_| format!("bad number {v:?}"))).collect()
}

impl Model {
    fn parse(text: &str) -> Result<Model, String> {
        let (mut mean, mut scale, mut weights, mut bias) = (None, None, None, None);
        for line in text.lines() {
            let parts: Vec<&str> = line.split_whitespace().collect();
            let Some((&name, values)) = parts.split_first() else {
                continue;
            };
            let values = numbers(values)?;
            match name {
                "mean" => mean = Some(values),
                "scale" => scale = Some(values),
                "weights" => weights = Some(values),
                "bias" if values.len() == 1 => bias = Some(values[0]),
                _ => return Err(format!("unexpected line {line:?}")),
            }
        }
        let mean = mean.ok_or("missing mean")?;
        let scale = scale.ok_or("missing scale")?;
        let weights = weights.ok_or("missing weights")?;
        let bias = bias.ok_or("missing bias")?;
        if mean.len() != weights.len() || scale.len() != weights.len() {
            return Err("mean, scale and weights must have the same length".to_string());
        }
        Ok(Model { mean, scale, weights, bias })
    }

    fn predict(&self, x: &[f64]) -> f64 {
        let mut z = self.bias;
        for i in 0..self.weights.len() {
            z += self.weights[i] * (x[i] - self.mean[i]) / self.scale[i];
        }
        1.0 / (1.0 + (-z).exp())
    }
}

@@tests
const TEXT: &str = "mean 10.0 1.5
scale 200.0 1.0

weights 1.2 0.5
bias -0.25";

/// Parses the four parts
#[test]
fn parses() {
    let m = Model::parse(TEXT).unwrap();
    assert_eq!(m.weights, vec![1.2, 0.5]);
    assert_eq!(m.bias, -0.25);
}

/// Predicts with standardisation and the sigmoid
#[test]
fn predicts() {
    let m = Model::parse(TEXT).unwrap();
    let z: f64 = -0.25 + 1.2 * (210.0 - 10.0) / 200.0 + 0.5 * (2.5 - 1.5);
    assert!((m.predict(&[210.0, 2.5]) - 1.0 / (1.0 + (-z).exp())).abs() < 1e-12);
}

/// Lines can come in any order
#[test]
fn any_order() {
    assert!(Model::parse("bias 0\nweights 1\nscale 1\nmean 0").is_ok());
}

/// Rejects broken files
#[test]
fn errors() {
    assert!(Model::parse("mean 0\nscale 1\nweights 1").is_err(), "missing bias");
    assert!(Model::parse("mean 0\nscale 1\nweights 1 2\nbias 0").is_err(), "length mismatch");
    assert!(Model::parse("mean x\nscale 1\nweights 1\nbias 0").is_err(), "bad number");
    assert!(Model::parse("mean 0\nscale 1\nweights 1\nbias 0\noffset 3").is_err(), "unknown line");
}

@@hint
Keep four `Option`s and fill them as you read lines. `parts.split_first()` gives you the name and the rest. At the end, `mean.ok_or("missing mean")?` turns each `None` into an error (a `&str` error converts to `String` automatically with `?`).
