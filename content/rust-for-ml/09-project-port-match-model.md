This project rehearses the most important skill in deploying ML: **moving a model between languages without changing its behaviour**. You'll train a home/draw/away model on the course's match data in Python, export it, then rebuild everything it needs in Rust:

1. the **features**, computed exactly as in training (a leak-free Elo rating and the market's home probability),
2. the **model**: a standard scaler followed by multinomial logistic regression,
3. the **evaluation**: log loss on the held-out season.

If any step differs even slightly (a feature in a different order, a different Elo update, a scaler fitted on different data), predictions drift and nobody notices until money is lost. So you'll test the Rust version against numbers produced by Python.

## Step 0: train and export in Python

Run this cell. It builds the features, trains the model on two seasons (keeping the third for testing), and exports it:

```python
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("data/matches.csv", parse_dates=["Date"]).sort_values("Date", kind="stable").reset_index(drop=True)

# Leak-free Elo: each match's feature uses ratings from BEFORE the match, then updates them.
ratings, elo_diff = {}, []
for home, away, result in zip(df.HomeTeam, df.AwayTeam, df.FTR):
    rh, ra = ratings.get(home, 1500.0), ratings.get(away, 1500.0)
    elo_diff.append(rh - ra)
    expected = 1 / (1 + 10 ** (-(rh - ra) / 400))
    score = {"H": 1.0, "D": 0.5, "A": 0.0}[result]
    ratings[home] = rh + 20 * (score - expected)
    ratings[away] = ra - 20 * (score - expected)
df["EloDiff"] = elo_diff

# The market's home-win probability, with the bookmaker's margin removed.
inverse = 1 / df[["AvgH", "AvgD", "AvgA"]]
df["MarketHome"] = inverse["AvgH"] / inverse.sum(axis=1)

FEATURES = ["EloDiff", "MarketHome"]
train, test = df[df.Season != "2024-25"], df[df.Season == "2024-25"]
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(train[FEATURES], train["FTR"])
probs = model.predict_proba(test[FEATURES])

print("classes:", list(model.classes_))
print("test log loss: model", round(log_loss(test["FTR"], probs, labels=model.classes_), 4))
market = inverse[df.Season == "2024-25"].to_numpy()
market = market[:, [2, 1, 0]] / market.sum(axis=1, keepdims=True)    # reorder to A, D, H
print("test log loss: market", round(log_loss(test["FTR"], market, labels=model.classes_), 4))

# Export the model as Rust source code (each cell runs on its own, so this lives in the same cell).
print()
scaler, clf = model.named_steps["standardscaler"], model.named_steps["logisticregression"]
fmt = lambda values: ", ".join(f"{v:.12}" for v in values)

print("// Generated from Python: StandardScaler + LogisticRegression on [EloDiff, MarketHome].")
print("// Class order: [away, draw, home].")
print(f"const MEAN: [f64; 2] = [{fmt(scaler.mean_)}];")
print(f"const SCALE: [f64; 2] = [{fmt(scaler.scale_)}];")
print("const WEIGHTS: [[f64; 2]; 3] = [")
for row in clf.coef_:
    print(f"    [{fmt(row)}],")
print("];")
print(f"const BIAS: [f64; 3] = [{fmt(clf.intercept_)}];")

print("\n// Check values: test rows and Python's probabilities")
for (_, row), p in zip(test.head(3).iterrows(), probs[:3]):
    print(f"// elo_diff {row.EloDiff!r}, odds {row.AvgH} {row.AvgD} {row.AvgA} -> {[round(float(x), 9) for x in p]}")
```

Note `classes: ['A', 'D', 'H']`: scikit-learn sorts the labels, so every probability array is in the order away, draw, home. Getting that order wrong is a classic porting bug.

The second half of the cell writes the model as **Rust source code**, ready to paste into a Rust file. This is the same "export the numbers" route as lesson 8, and exactly how Phase 13 gets a model onto a microcontroller.

The constants in the exercises below were generated by exactly this cell. (If your browser's numbers differ in the last few digits, that's floating-point noise between Python builds, far below the tolerance of the tests.)

use std::collections::HashMap;

fn elo_diffs(matches: &[(&str, &str, char)]) -> Vec<f64> {
    let mut ratings: HashMap<&str, f64> = HashMap::new();
    let mut out = Vec::with_capacity(matches.len());
    for &(home, away, result) in matches {
        let rh = *ratings.get(home).unwrap_or(&1500.0);
        let ra = *ratings.get(away).unwrap_or(&1500.0);
        let diff = rh - ra;
        out.push(diff);
        let expected = 1.0 / (1.0 + 10f64.powf(-diff / 400.0));
        let score = match result {
            'H' => 1.0,
            'D' => 0.5,
            _ => 0.0,
        };
        let change = 20.0 * (score - expected);
        ratings.insert(home, rh + change);
        ratings.insert(away, ra - change);
    }
    out
}

@@tests

    (a - b).abs() < 1e-9
}

#[test]
fn first_round() {
    let d = elo_diffs(&[("A", "B", 'H'), ("C", "D", 'D')]);
    assert_eq!(d, vec![0.0, 0.0]);
}

/// Uses ratings from before each match
#[test]
fn second_round() {
    // A beats B: A 1510, B 1490. Then B v A: diff = 1490 - 1510 = -20
    let d = elo_diffs(&[("A", "B", 'H'), ("B", "A", 'A')]);
    assert!(close(d[1], -20.0), "got {d:?}");

const MEAN: [f64; 2] = [0.966377318312, 0.437445836999];
const SCALE: [f64; 2] = [61.3934370946, 0.0954058677913];
const WEIGHTS: [[f64; 2]; 3] = [
    [-0.05448317431, -0.183705998732],
    [-0.0140736074829, 0.0331379079152],
    [0.068556781793, 0.150568090817],
];
const BIAS: [f64; 3] = [-0.0888058158958, -0.243132743933, 0.331938559829];

fn market_home(odds_home: f64, odds_draw: f64, odds_away: f64) -> f64 {
    let (h, d, a) = (1.0 / odds_home, 1.0 / odds_draw, 1.0 / odds_away);
    h / (h + d + a)
}

fn predict_proba(elo_diff: f64, odds: [f64; 3]) -> [f64; 3] {
    let raw = [elo_diff, market_home(odds[0], odds[1], odds[2])];
    let mut x = [0.0; 2];
    for i in 0..2 {
        x[i] = (raw[i] - MEAN[i]) / SCALE[i];
    }
    let mut z = [0.0; 3];
    for k in 0..3 {
        z[k] = BIAS[k] + WEIGHTS[k][0] * x[0] + WEIGHTS[k][1] * x[1];
    }
    let max = z.iter().cloned().fold(f64::NEG_INFINITY, f64::max);
    let e = [(z[0] - max).exp(), (z[1] - max).exp(), (z[2] - max).exp()];
    let total = e[0] + e[1] + e[2];
    [e[0] / total, e[1] / total, e[2] / total]
}

@@solution
fn class_index(outcome: char) -> usize {
    match outcome {
        'A' => 0,
        'D' => 1,
        _ => 2,
    }
}

fn multiclass_log_loss(probs: &[[f64; 3]], outcomes: &[char]) -> f64 {
    let total: f64 = probs
        .iter()
        .zip(outcomes)
        .map(|(p, &o)| -p[class_index(o)].max(1e-15).ln())
        .sum();
    total / probs.len() as f64
}

fn market_probs(odds: [f64; 3]) -> [f64; 3] {
    let inv = [1.0 / odds[0], 1.0 / odds[1], 1.0 / odds[2]];
    let total = inv[0] + inv[1] + inv[2];
    [inv[2] / total, inv[1] / total, inv[0] / total]
}

@@tests
/// Matches sklearn.metrics.log_loss
#[test]
fn log_loss_value() {
    let probs = [[0.2, 0.3, 0.5], [0.6, 0.3, 0.1], [0.1, 0.8, 0.1]];
    let ll = multiclass_log_loss(&probs, &['H', 'A', 'D']);
    let want = -(0.5f64.ln() + 0.6f64.ln() + 0.8f64.ln()) / 3.0;
    assert!((ll - want).abs() < 1e-12, "got {ll}");
}

/// A zero probability is clamped, not infinite
#[test]
fn clamped() {
    assert!(multiclass_log_loss(&[[0.0, 0.0, 1.0]], &['A']).is_finite());
}

/// Market probabilities come back as away, draw, home
#[test]
fn market_order() {
    let p = market_probs([2.0, 4.0, 4.0]);
    assert!((p[0] - 0.25).abs() < 1e-12 && (p[2] - 0.5).abs() < 1e-12, "got {p:?}");
    assert!((p.iter().sum::<f64>() - 1.0).abs() < 1e-12);
}

## What you've proved

Your Rust code now reproduces the Python pipeline exactly: same features, same model, same metric. From here you could:

- read `matches.csv` in Rust (the `csv` crate), compute features for the whole test season, and confirm you get the same test log loss as Python,
- serve `predict_proba` from an axum service (lesson 8),
- or convert it to fixed-point integers and run it on a microcontroller, which is exactly what Phase 13 does with a gesture model.

The workflow is always the same: **train in Python, export the numbers and a few check values, re-implement the forward pass, and test the two against each other.**
